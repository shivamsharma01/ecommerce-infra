MCART E-Commerce — GCP/GKE Deployment & Operations Guide
1. Install Google Cloud CLI (gcloud) on Linux

Download the Google Cloud CLI:

curl -O https://dl.google.com/dl/cloudsdk/channels/rapid/downloads/google-cloud-cli-linux-x86_64.tar.gz

Extract the archive:

tar -xf google-cloud-cli-linux-x86_64.tar.gz

Go into the extracted directory:

cd google-cloud-sdk/

Run the installer:

./google-cloud-sdk/install.sh

Initialize gcloud:

gcloud init

Follow the prompts to:

Sign in with your Google account.
Select the appropriate GCP project.
Configure the default settings.
2. Kubernetes (kubectl) Basic Commands
2.1 Restart a Deployment

To restart the search service:

kubectl rollout restart deployment search -n mcart

This performs a rolling restart of the deployment.

2.2 Delete Pods and Let Kubernetes Recreate Them

Alternatively, you can delete the pods belonging to a service.

For example:

kubectl delete pod -l app=search -n mcart

If the pods are managed by a Deployment, Kubernetes will automatically create replacement pods.

2.3 Watch Pod Status
kubectl get pods -n mcart -w

The -w option continuously watches the pod status.

Press:

Ctrl + C

to stop watching.

3. GKE Gateway Deployment Flow

This is the new Gateway deployment flow, starting from Terraform infrastructure and ending with HTTPS, OIDC and JWT validation.

Step 0 — Provision Infrastructure Using Terraform

Navigate to the Terraform directory:

cd ~/project/mcart/ecomm-infra/terraform
0.1 Clear Google Application Credentials
unset GOOGLE_APPLICATION_CREDENTIALS
0.2 Set the GCP Project
gcloud config set project ecommerce-491019

Verify:

gcloud config get-value project

Expected project:

ecommerce-491019
0.3 Authenticate Application Default Credentials
gcloud auth application-default login

Follow the browser-based authentication flow.

0.4 Initialize Terraform
terraform init
0.5 Create Terraform Plan
terraform plan -out=tfplan

Review the plan before applying it.

0.6 Apply Terraform Plan
terraform apply tfplan
0.7 Get the Reserved Gateway IP

This is optional but useful:

terraform output -raw mcart_gateway_static_ip_address

Save this IP because it will later be associated with the Envoy Gateway LoadBalancer and DNS.

4. Connect to the GKE Cluster

Retrieve the GKE cluster credentials:

gcloud container clusters get-credentials mcart-gke \
  --location asia-south2-a \
  --project ecommerce-491019

Verify that the cluster is accessible:

kubectl get nodes

Check available namespaces:

kubectl get ns
5. Install Data Dependencies

Navigate to the deployment directory:

cd ~/project/mcart/ecomm-infra/deploy

Install the required data dependencies:

make data-install data-install-redis data-install-es

Check the resulting pods:

kubectl -n mcart get pods
6. Bootstrap Databases Using Flyway

Set the database passwords.

export AUTH_PASS='MY_PASSWORD'
export USER_PASS='MY_PASSWORD'

Create temporary password files with restricted permissions:

printf '%s' "$AUTH_PASS" > /tmp/auth.db.pass
chmod 600 /tmp/auth.db.pass

printf '%s' "$USER_PASS" > /tmp/user.db.pass
chmod 600 /tmp/user.db.pass

Run the Flyway installation:

make flyway-install \
  AUTH_DB_PASS_FILE=/tmp/auth.db.pass \
  USER_DB_PASS_FILE=/tmp/user.db.pass

After Flyway completes, remove the temporary password files:

rm -f /tmp/auth.db.pass /tmp/user.db.pass
7. Deploy the MCART Applications

From the deployment directory:

make apps-apply NS=mcart

Check the pods:

kubectl get pods -n mcart

Check deployments:

kubectl get deploy -n mcart
7.1 Application Sanity Checks

Check that Product can communicate with Auth:

kubectl exec -n mcart deploy/product -c product -- \
  curl -i http://auth:8081/actuator/health/liveness

Check that Product can communicate with Search:

kubectl exec -n mcart deploy/product -c product -- \
  curl -i http://search:80/health/readiness

These checks confirm that the deployed services are reachable from within the cluster.

8. Install Envoy Gateway and cert-manager

Navigate to the deployment directory:

cd ~/project/mcart/ecomm-infra/deploy

This section installs:

Envoy Gateway controller
Gateway API CRDs
cert-manager
Gateway-related MCART resources
JWT/security configuration
TLS certificate configuration
8.1 Install Envoy Gateway

Apply the Envoy Gateway installation:

kubectl apply --server-side \
  -f "https://github.com/envoyproxy/gateway/releases/download/v1.7.1/install.yaml"

Wait until the Envoy Gateway deployment becomes available:

kubectl wait --timeout=5m \
  -n envoy-gateway-system \
  deployment/envoy-gateway \
  --for=condition=Available
8.2 Install cert-manager

Add the Jetstack Helm repository:

helm repo add jetstack https://charts.jetstack.io

Update Helm repositories:

helm repo update

Install cert-manager:

helm upgrade --install cert-manager jetstack/cert-manager \
  --namespace cert-manager \
  --create-namespace \
  --version v1.16.3 \
  --set crds.enabled=true \
  --set config.enableGatewayAPI=true

Wait for cert-manager:

kubectl wait --timeout=5m \
  -n cert-manager \
  deploy/cert-manager \
  --for=condition=Available

Wait for the webhook:

kubectl wait --timeout=5m \
  -n cert-manager \
  deploy/cert-manager-webhook \
  --for=condition=Available

Wait for the CA injector:

kubectl wait --timeout=5m \
  -n cert-manager \
  deploy/cert-manager-cainjector \
  --for=condition=Available

Verify the cert-manager CRD:

kubectl get crd | grep certificaterequests
9. Apply MCART Gateway Resources

From:

cd ~/project/mcart/ecomm-infra/deploy

Apply the Gateway configuration:

make gateway-apply

This applies the MCART Gateway resources, including:

Gateway
HTTPRoutes
JWT/security configuration
ClusterIssuer
Certificate

Verify the Gateway:

kubectl get gateway -n mcart-gateway

Verify HTTP routes:

kubectl get httproute -n mcart-gateway

Verify security policies:

kubectl get securitypolicy -n mcart-gateway
10. Bind the Reserved Static IP to Envoy Gateway

Envoy Gateway creates the LoadBalancer Service automatically.

The next step is to associate the Terraform-reserved static IP with that service.

10.1 Get the Reserved IP
GW_IP=$(cd ~/project/mcart/ecomm-infra/terraform && \
  terraform output -raw mcart_gateway_static_ip_address)

Print it:

echo "$GW_IP"
10.2 Find the Envoy LoadBalancer Service
ENVOY_SVC=$(kubectl get svc -n envoy-gateway-system \
  --selector gateway.envoyproxy.io/owning-gateway-namespace=mcart-gateway,gateway.envoyproxy.io/owning-gateway-name=mcart \
  -o jsonpath='{.items[0].metadata.name}')

Print the service name:

echo "$ENVOY_SVC"
10.3 Patch the Service

Assign the Terraform-reserved IP:

kubectl -n envoy-gateway-system patch svc "$ENVOY_SVC" \
  -p "{\"spec\":{\"loadBalancerIP\":\"$GW_IP\"}}"

Watch the LoadBalancer:

kubectl -n envoy-gateway-system get svc "$ENVOY_SVC" -w

Wait until the external IP is associated with the service.

11. Configure DNS

The following domains should point to the reserved Gateway IP:

mcart.space
www.mcart.space

Get the IP again if required:

cd ~/project/mcart/ecomm-infra/terraform

terraform output -raw mcart_gateway_static_ip_address

The DNS records should point to this IP.

According to the deployment setup, Terraform can manage Cloud DNS if:

create_cloud_dns_public_zone=true

If Cloud DNS is not being managed through Terraform, configure the DNS records through your registrar/DNS provider instead.

12. Validate HTTPS, OIDC and JWT

Once DNS is configured, verify that cert-manager has issued the TLS certificate.

12.1 Check Certificate and Secret
kubectl -n mcart-gateway get certificate,secret

Describe the certificate:

kubectl -n mcart-gateway describe certificate mcart-tls
13. Test Public Endpoints

The following endpoints should be accessible without an access token.

OIDC Discovery
curl -i https://mcart.space/.well-known/openid-configuration
JWKS
curl -i https://mcart.space/oauth2/jwks
Root Endpoint
curl -i https://mcart.space/
14. Test JWT-Protected Endpoints

The following endpoints should return:

401 Unauthorized

when no token is supplied.

Products
curl -i https://mcart.space/api/products
User
curl -i https://mcart.space/user
14.1 Test With an Access Token

Set the access token:

TOKEN="paste_access_token_here"

Call the protected Products API:

curl -i \
  -H "Authorization: Bearer ${TOKEN}" \
  https://mcart.space/api/products

This verifies that the Gateway accepts a valid JWT.

15. Kubernetes Logs
15.1 View Logs for a Deployment

Replace:

PRODUCT_DEPLOYMENT
NAMESPACE

with the appropriate values.

kubectl logs deploy/PRODUCT_DEPLOYMENT \
  -n NAMESPACE \
  --tail=200 \
  -f

For example:

kubectl logs deploy/product \
  -n mcart \
  --tail=200 \
  -f
16. View Logs for All Pods With a Label
kubectl logs \
  -n NAMESPACE \
  -l app.kubernetes.io/name=mcart-product \
  --tail=100 \
  -f \
  --prefix \
  --max-log-requests=20

This is useful when multiple pods belonging to the same application are running.

17. View Logs Using Google Cloud Logging

Use:

gcloud logging read \
  'resource.type="k8s_container"
   resource.labels.namespace_name="NAMESPACE"
   resource.labels.cluster_name="CLUSTER_NAME"' \
  --limit=50 \
  --format='table(timestamp,resource.labels.pod_name,jsonPayload.message,textPayload)' \
  --freshness=1h

Replace:

NAMESPACE
CLUSTER_NAME

with the appropriate values.

For example, the namespace would typically be:

mcart
18. Google Cloud Logs Explorer

You can also inspect Kubernetes logs through the Google Cloud Console.

Go to:

Logging → Logs Explorer

Use the query builder with:

resource.type="k8s_container"

You can further filter using:

namespace_name
pod_name
container_name

or perform a text search for a particular error/message.

19. Deployment Deletion / Cleanup

Warning: The following commands delete Kubernetes resources and Terraform-managed infrastructure. Review them before running them.

19.1 Delete the MCART Namespace
kubectl delete namespace mcart \
  --ignore-not-found \
  --timeout=120s
19.2 Delete Gateway Resources

Navigate to the deployment directory:

cd ~/mcart/ecomm-infra/deploy

Delete Gateway manifests:

kubectl delete -f k8s/gateway/ \
  --ignore-not-found

Delete the Gateway namespace:

kubectl delete namespace mcart-gateway \
  --ignore-not-found \
  --timeout=120s

Delete Envoy Gateway:

kubectl delete namespace envoy-gateway-system \
  --ignore-not-found \
  --timeout=120s

Delete the GatewayClass:

kubectl delete gatewayclass envoy-gateway \
  --ignore-not-found
20. Remove cert-manager

Uninstall cert-manager:

helm uninstall cert-manager \
  -n cert-manager \
  --ignore-not-found

Delete its namespace:

kubectl delete namespace cert-manager \
  --ignore-not-found \
  --timeout=120s

Delete the Envoy Gateway installation:

kubectl delete \
  --ignore-not-found \
  -f "https://github.com/envoyproxy/gateway/releases/download/v1.7.1/install.yaml"
21. Clean Up GKE LoadBalancer Firewalls

Before destroying the Terraform infrastructure, check the forwarding rules:

gcloud compute forwarding-rules list \
  --project=ecommerce-491019 \
  --regions=asia-south2

Navigate to Terraform:

cd ~/mcart/ecomm-infra/terraform

Set the project and network:

export PROJECT_ID=ecommerce-491019
export NETWORK_NAME=mcart-vpc

Run the GKE LoadBalancer firewall cleanup:

bash scripts/gke_lb_firewall_cleanup.sh
22. Optional Firestore cart_items Cleanup

Install the Google Cloud Firestore Python library:

pip3 install --user google-cloud-firestore

This is listed as an optional cleanup step for cart_items documents during destruction.

23. Destroy Terraform Infrastructure

The preferred destroy command is:

make destroy

Alternatively:

./scripts/destroy-preserve-firestore-indexes.sh
Important

Do not use:

terraform destroy

if you want to preserve the Firestore composite indexes.

The deployment setup specifically indicates that the provided destroy flow preserves the Firestore composite indexes so that they don't have to be rebuilt/re-waited on during the next deployment.

24. Complete Deployment Flow — Quick Reference

For a fresh GCP/GKE deployment, the sequence is:

1. Install gcloud
        ↓
2. Authenticate with GCP
        ↓
3. Terraform init
        ↓
4. Terraform plan
        ↓
5. Terraform apply
        ↓
6. Get GKE credentials
        ↓
7. Verify cluster
        ↓
8. Install PostgreSQL / Redis / Elasticsearch dependencies
        ↓
9. Run Flyway database bootstrap
        ↓
10. Deploy MCART applications
        ↓
11. Verify application pods
        ↓
12. Install Envoy Gateway
        ↓
13. Install cert-manager
        ↓
14. Apply MCART Gateway resources
        ↓
15. Bind reserved static IP
        ↓
16. Configure DNS
        ↓
17. Wait for TLS certificate
        ↓
18. Validate HTTPS
        ↓
19. Validate OIDC endpoints
        ↓
20. Validate JWT-protected APIs
        ↓
21. Deployment complete
