MCART E-Commerce — Complete Local Setup Guide
1. Prerequisites

Make sure the following are available on the Linux machine:

Docker
PostgreSQL container
Redis container
Google Cloud CLI (gcloud)
Gradle / project Gradle wrapper
Access to the MCART repositories
GCP project and service-account credentials where required

Project/deployment directory used by the setup:

cd /home/shivam-sharma/project/mcart/ecomm-infra/deploy
2. Start PostgreSQL and Redis

Start the PostgreSQL container:

docker run -d \
  --name postgres-db \
  -p 5433:5432 \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  postgres:16

Start Redis:

docker run -d \
  --name auth-redis \
  -p 6379:6379 \
  -v redis-data:/data \
  redis:7 \
  redis-server --appendonly yes --requirepass myStrongRedisPassword

The PostgreSQL instance is exposed on:

localhost:5433

Redis is exposed on:

localhost:6379
3. Create PostgreSQL Users and Databases

The ecommerce setup contains separate databases/users for each PostgreSQL-backed service.

Run:

docker exec -i postgres-db psql -U postgres <<'SQL'
CREATE USER auth_user WITH PASSWORD 'auth_password';
CREATE DATABASE auth OWNER auth_user;
GRANT ALL PRIVILEGES ON DATABASE auth TO auth_user;
SQL
docker exec -i postgres-db psql -U postgres <<'SQL'
CREATE USER user_user WITH PASSWORD 'user_password';
CREATE DATABASE "user" OWNER user_user;
SQL
docker exec -i postgres-db psql -U postgres <<'SQL'
CREATE USER inventory_user WITH PASSWORD 'inventory_password';
CREATE DATABASE inventory OWNER inventory_user;
GRANT ALL PRIVILEGES ON DATABASE inventory TO inventory_user;

CREATE USER cart_user WITH PASSWORD 'cart_password';
CREATE DATABASE cart OWNER cart_user;
GRANT ALL PRIVILEGES ON DATABASE cart TO cart_user;

CREATE USER payment_user WITH PASSWORD 'payment_password';
CREATE DATABASE payment OWNER payment_user;
GRANT ALL PRIVILEGES ON DATABASE payment TO payment_user;

CREATE USER order_user WITH PASSWORD 'order_password';
CREATE DATABASE "order" OWNER order_user;
GRANT ALL PRIVILEGES ON DATABASE "order" TO order_user;
SQL
Databases created
Service	Database	User
Auth	auth	auth_user
User	user	user_user
Inventory	inventory	inventory_user
Cart	cart	cart_user
Payment	payment	payment_user
Order	order	order_user

Note: The first document says Cart uses Firestore rather than PostgreSQL/Flyway, while the ecommerce document explicitly creates a Cart PostgreSQL database and runs its Flyway migration. The merged setup follows the ecommerce document, where Cart has its own PostgreSQL database.

5. Configure GCP Credentials

Set the GCP project:

gcloud config set project "${GCP_PROJECT_ID:?Set GCP_PROJECT_ID}"

Set the service-account credentials path:

export GOOGLE_APPLICATION_CREDENTIALS="${GOOGLE_APPLICATION_CREDENTIALS:?Set path to your GCP service account key JSON}"

The credentials JSON should not be committed to source control.

6. Configure GCP Services and Pub/Sub

Enable the required services:

gcloud services enable \
  firestore.googleapis.com \
  pubsub.googleapis.com

Set the project:

gcloud config set project "${GCP_PROJECT_ID:?Set GCP_PROJECT_ID}"

8. Configure GCP IAM Permissions

Replace:

YOUR_GCP_PROJECT
YOUR_FIRESTORE_SA

with the actual values.

Pub/Sub publisher

  --member="serviceAccount:YOUR_FIRESTORE_SA@YOUR_GCP_PROJECT.iam.gserviceaccount.com" \
  --role="roles/pubsub.publisher"
Pub/Sub subscriber
gcloud projects add-iam-policy-binding YOUR_GCP_PROJECT \
  --member="serviceAccount:YOUR_FIRESTORE_SA@YOUR_GCP_PROJECT.iam.gserviceaccount.com" \
  --role="roles/pubsub.subscriber"
Cloud Storage object creator
gcloud projects add-iam-policy-binding YOUR_GCP_PROJECT \
  --member="serviceAccount:YOUR_FIRESTORE_SA@YOUR_GCP_PROJECT.iam.gserviceaccount.com" \
  --role="roles/storage.objectCreator"
9. Local Pub/Sub Emulator — Linux Setup

If you want to run Pub/Sub locally without using the actual GCP Pub/Sub service, use the Pub/Sub emulator.

Start the emulator:

docker run -d \
  --name pubsub-emulator \
  -p 8086:8085 \
  google/cloud-sdk:latest \
  gcloud beta emulators pubsub start \
  --host-port=0.0.0.0:8085

The original document has a small port inconsistency: the Docker container maps 8086:8085, so the host endpoint is localhost:8086. However, the subsequent application configuration and curl health check in the document use both 8085 and 8086. The commands below preserve the intended mapping and make the host port explicit.

Check the emulator:

curl http://localhost:8086
10. Configure Services to Use the Pub/Sub Emulator

In each service's application-local.yaml, locate the GCP configuration.

The original configuration contains:

cloud:
  gcp:
    project-id: "${MCART_GCP_PROJECT_ID:${SPRING_CLOUD_GCP_PROJECT_ID:my-project-chat-ai-487408}}"
    credentials:
      location: ${GCP_CREDENTIALS_PATH:}
    pubsub:
      enabled: ${SPRING_CLOUD_GCP_PUBSUB_ENABLED:true}

For local emulator usage, remove the credentials configuration and add the emulator host:

cloud:
  gcp:
    project-id: "${MCART_GCP_PROJECT_ID:${SPRING_CLOUD_GCP_PROJECT_ID:my-project-chat-ai-487408}}"
    pubsub:
      enabled: ${SPRING_CLOUD_GCP_PUBSUB_ENABLED:true}
      emulator-host: "localhost:8086"

The source document shows localhost:8085 in one version of the YAML despite the Docker mapping using host port 8086; this should be kept consistent with whichever host port you actually expose.

11. Create Pub/Sub Topics Locally

With the emulator running, create the topics and subscriptions.

Email verification
curl -X PUT \
  "http://localhost:8086/v1/projects/my-project-chat-ai-487408/topics/email-verification-events"

Create the subscription:

curl -X PUT \
  "http://localhost:8086/v1/projects/my-project-chat-ai-487408/subscriptions/email-verification-events-sub" \
  -H "Content-Type: application/json" \
  -d '{
    "topic": "projects/my-project-chat-ai-487408/topics/email-verification-events"
  }'
User signup
curl -X PUT \
  "http://localhost:8086/v1/projects/my-project-chat-ai-487408/topics/user-signup-events"

Create the subscription:

curl -X PUT \
  "http://localhost:8086/v1/projects/my-project-chat-ai-487408/subscriptions/user-signup-events-sub" \
  -H "Content-Type: application/json" \
  -d '{
    "topic": "projects/my-project-chat-ai-487408/topics/user-signup-events"
  }'

Create the remaining topics/subscriptions in the same way for the other services that require them.

12. Firestore Emulator — Product Service

The product service also requires a Firestore emulator for local setup.

Run:

docker run -d \
  --name firestore-emulator \
  -p 8090:8080 \
  -p 4000:4000 \
  andreysenov/firebase-tools:latest \
  firebase emulators:start \
  --only firestore \
  --project demo-project

This exposes:

Firestore emulator: localhost:8090
Firestore UI:       localhost:4000

The original document specifies this as a separate requirement for the product service.

13. Email SMTP Configuration

For local email testing, configure Gmail SMTP in the appropriate application-local.yaml.

mail:
  host: smtp.gmail.com
  port: ${SPRING_MAIL_PORT:587}
  username: "<your email id>"
  password: "your APP Password not Gmail password."
  properties:
    mail:
      smtp:
        auth: true
        startttls:
          enable: true

Use a Gmail App Password, not the normal Gmail account password.

Alternatively, the service can use environment variables:

export SPRING_MAIL_USERNAME="${SPRING_MAIL_USERNAME:?Set SMTP username}"
export SPRING_MAIL_PASSWORD="${SPRING_MAIL_PASSWORD:?Set SMTP app password}"

Do not commit SMTP passwords to source control.

16. Start All Services Using Script

If all repositories have been cloned under the same location and the project contains the scripts mentioned in the document, use:

./start_services.sh

To stop all services:

./stop_services.sh

The source document specifically references these scripts for starting/stopping all microservices.

17. Check for Port Conflicts

To check whether port 8081 is already being used:

lsof -i :8081

Stop the process using the returned PID:

kill <PID>

The original setup uses this specifically for resolving a service/port conflict.
